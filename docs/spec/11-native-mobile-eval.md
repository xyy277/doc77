# 原生移动 App 评估 — 设计文档

> 日期: 2026-07-27 | 优先级: Q1-2027-3（评估阶段） | 状态: 评估/决策

## 一、背景

经过 Spec 1（PWA）和 Spec 6（远程隧道）后，移动端已具备：
- PWA 添加到主屏幕 + 离线缓存
- 远程安全访问（Cloudflare Tunnel / Tailscale）

但仍存在 PWA 无法覆盖的场景：
- 后台同步（PWA 无法持久后台运行）
- 系统级文件共享（"用 Doc77 打开"）
- 推送通知可靠性（PWA push 在 iOS 受限）
- 相机/相册直接上传到 Doc77
- 离线编辑 + 后续同步

**本 spec 是评估文档**，分析是否需要原生 App、何时做、怎么做。

## 二、决策矩阵

### 2.1 PWA vs 原生 App 对比

| 维度 | PWA（已实现） | 原生 App |
|------|-------------|---------|
| 安装成本 | 零（浏览器即用） | 需下载 50-100MB |
| 离线能力 | 有限（SW 缓存） | 完整（本地 SQLite） |
| 后台同步 | ❌ 不支持 | ✅ 后台任务 |
| 推送通知 | iOS 受限 | ✅ 完整 |
| 系统集成 | 弱 | 强（文件/相机/分享） |
| 开发成本 | 已完成 | 6-10 周额外 |
| 维护成本 | 低（一套代码） | 高（iOS + Android） |
| 更新 | 即时（服务端） | 需应用商店审核 |
| 分发 | 无限制 | App Store / Play Store 规则 |

### 2.2 何时需要原生 App？

**触发条件**（满足 2+ 时考虑启动）：
- [ ] 用户量 > 1000 且移动端使用率 > 30%
- [ ] "后台同步"成为 Top 3 用户反馈
- [ ] iOS PWA 推送限制严重影响审批流程
- [ ] 有明确的"手机拍照 → 自动同步到 Doc77"需求
- [ ] 竞品（如 Obsidian、Notion）移动端体验形成压力

**当前判断**：暂不启动原生 App 开发。PWA + 隧道已覆盖 80% 移动场景。

## 三、技术选型评估（若决定做）

### 3.1 方案对比

| 方案 | 优势 | 劣势 | 适合 |
|------|------|------|------|
| **Capacitor** | 复用现有 Web UI、一套代码、Ionic 生态 | 性能一般、原生感弱 | 快速出 MVP |
| **React Native** | 原生性能、社区大、热更新 | 需重写 UI、学习曲线 | 长期投入 |
| **Flutter** | 高性能、UI 一致、Dart 生态 | 需全新代码、与现有 TS 栈断裂 | 追求极致体验 |
| **Tauri Mobile** | Rust 核心、极小体积、复用 Web | 2026 年仍较新、移动端生态不成熟 | 技术前瞻 |
| **Expo (RN)** | RN + 简化构建 + OTA 更新 | 同 RN | RN 首选 |

### 3.2 推荐方案：Capacitor（若启动）

理由：
- **最大化复用**：现有 Web UI（HTML/CSS/JS）直接运行在 WebView
- **增量原生**：需要原生能力时通过 Capacitor Plugin 桥接
- **成本最低**：不需要重写前端，1-2 人 4-6 周可出 MVP
- **与 PWA 共存**：同一套 Web 代码，PWA 和 App 共享

```
packages/mobile/          (新增，若启动)
├── capacitor.config.ts
├── ios/                  (Xcode 项目)
├── android/              (Gradle 项目)
├── src/
│   ├── plugins/
│   │   ├── background-sync.ts   # 后台同步
│   │   ├── file-share.ts        # 系统分享
│   │   ├── camera-upload.ts     # 拍照上传
│   │   └── push-notification.ts # 原生推送
│   └── native-bridge.ts         # 与 Doc77 server 通信
└── package.json
```

## 四、原生 App 功能规划（若启动）

### Phase 1：阅读器 MVP（4 周）

| 功能 | 说明 |
|------|------|
| 连接服务器 | 输入 URL / 扫码连接 Doc77 实例 |
| 文档浏览 | 复用 Web UI（WebView） |
| 离线缓存 | 本地 SQLite 缓存已浏览文档 |
| 推送通知 | 审批提醒（FCM / APNs） |
| 基本设置 | 主题、字体大小 |

### Phase 2：同步客户端（4 周）

| 功能 | 说明 |
|------|------|
| 后台同步 | 定时拉取变更（iOS BGTask / Android WorkManager） |
| 本地存储 | 完整项目文件缓存到手机 |
| 离线阅读 | 无网络时阅读缓存文档 |
| 冲突处理 | 简化版（最后写入胜出 + 冲突列表） |

### Phase 3：创作工具（4 周）

| 功能 | 说明 |
|------|------|
| Markdown 编辑 | 移动端编辑器（简化版） |
| 拍照上传 | 相机/相册 → 直接上传到项目 |
| 语音笔记 | 录音 → 转文字 → 保存为 .md |
| 分享接收 | 系统"分享到 Doc77" |
| Widget | iOS/Android 桌面小组件（最近文档） |

## 五、架构设计（若启动）

### 5.1 通信模式

```
┌─ 手机 App ─────────────────────────────────────────┐
│                                                     │
│  ┌─ WebView ─┐    ┌─ Native Layer ─┐              │
│  │ Doc77 Web │    │ Capacitor       │              │
│  │ UI (复用) │◄──►│ Plugins         │              │
│  │           │    │ - Sync Engine   │              │
│  └───────────┘    │ - Push          │              │
│                   │ - File System   │              │
│                   │ - Camera        │              │
│                   └────────┬────────┘              │
│                            │                        │
└────────────────────────────┼────────────────────────┘
                             │ HTTPS / Tailscale
                             ▼
                   ┌─ Doc77 Server ─┐
                   │ (用户的电脑/NAS) │
                   └─────────────────┘
```

### 5.2 离线优先架构

```
手机本地 SQLite
  ├── documents (缓存的文档内容)
  ├── files (文件元数据)
  ├── sync_queue (待同步的本地修改)
  └── settings

同步策略:
  - 在线时: 实时同步（WebSocket / SSE）
  - 离线时: 修改入 sync_queue
  - 恢复在线: 按序重放 sync_queue
```

## 七、风险与缓解

| 风险 | 缓解 |
|------|------|
| iOS 审核拒绝（本地服务器连接） | 说明为"自托管文档阅读器"，无云端依赖 |
| WebView 性能（大文档） | 原生渲染降级（仅 Markdown 用原生 View） |
| 后台任务限制（iOS） | 使用 BGAppRefreshTask，接受 15min 间隔 |
| 维护两套代码 | Capacitor 最大化复用 Web，原生层仅插件 |
| 用户量不足以支撑 | 延迟启动，PWA 兜底 |

## 八、决策建议

### 当前（2026 Q3-Q4）：不启动

- PWA + 隧道已满足基本移动需求
- 优先投入同步引擎（Spec 4/5）和搜索（Spec 3）
- 收集移动端使用数据

### 触发评估（2027 Q1）：

- 若用户反馈强烈 + 使用数据支持 → 启动 Capacitor MVP
- 若 PWA 足够 → 继续增强 PWA（Spec 1 Phase 2: Web Push）

### 决策检查清单

```
□ 移动端 DAU > 总 DAU 的 20%
□ "后台同步" 反馈 > 10 条/月
□ PWA 推送在 iOS 上的打开率 < 30%
□ 有明确的"手机拍照上传"使用场景
□ 团队有 1 人可投入移动端维护
→ 满足 3+ → 启动 Capacitor Phase 1
```

## 九、验收标准（本 spec）

本 spec 为评估文档，验收标准为：
1. 决策矩阵完整，覆盖技术/成本/风险
2. 触发条件明确，避免过早投入
3. 若启动，Capacitor 方案可在 4 周内交付 MVP
4. 与现有 PWA 方案不冲突，可共存
